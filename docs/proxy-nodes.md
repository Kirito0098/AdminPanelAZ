# Прокси AntiZapret и прокси-узлы панели

Полная инструкция: **что это**, **где что лежит**, **как собрать схему** и **как работать** из панели. Только для **администратора**.

---

## Зачем это нужно

Клиент в России часто не может стабильно достучаться до зарубежного VPN напрямую. Схема AntiZapret:

1. Клиент подключается к **российскому прокси** (отдельный VPS).
2. Прокси пересылает трафик на **зарубежный VPN-сервер** (`DESTINATION`).
3. На VPN открывается обычная сессия OpenVPN / WireGuard.

Панель помогает:

- держать в `.ovpn` **несколько адресов** (прокси + серверы) в нужном порядке;
- **мониторить** RU-прокси и менять DESTINATION **без** повторного запуска `proxy.sh`;
- в **NOC** показывать **домашний IP** клиента, когда известен маппинг порта прокси.

Панель **никогда** не ставит и не запускает `proxy.sh` — это скрипт AntiZapret на RU VPS.

---

## Три разные вещи (не путать)

| Что | Где в панели | На какой машине | Зачем |
|-----|--------------|-----------------|-------|
| **VPN-узел** | **Узлы**, тип «VPN» | Зарубежный (или локальный) AntiZapret + `node_agent` **:9100** | Клиенты, конфиги, синхронизация, «активный узел» |
| **Прокси-узел** | **Узлы**, тип «Прокси» (модуль **Прокси-узлы**) | RU VPS + уже установленный `proxy.sh` + `proxy_agent` **:9101** | Статус прокси, смена DESTINATION, данные для NOC |
| **Адреса подключения** | **Конфиг AntiZapret → OpenVPN (панель)** | Хранятся в **БД панели** на VPN-узле | Несколько строк `remote` в `.ovpn` (и Endpoint WG при выдаче) |

Прокси-узел **нельзя активировать** как VPN: к нему не относятся конфиги, HA Push full и «активный узел».

Подробнее про список remote: [antizapret-config.md](antizapret-config.md#несколько-адресов-подключения).  
Установка агента на RU: [proxy-agent.md](proxy-agent.md).  
Страница узлов в целом: [uzly.md](uzly.md).

## Где что находится

### На машине с панелью

| Место | Что |
|-------|-----|
| **Настройки → Модули** → **Прокси-узлы** | Включение функции (`proxy_nodes`, по умолчанию **выкл.**) |
| **Конфигурация → Прокси** | Сводка: статус/DESTINATION прокси-узлов, адреса remote активного VPN, быстрые ссылки |
| **Узлы** | Карточки VPN и (если модуль вкл.) прокси: health, DESTINATION (CRUD прокси-узлов) |
| **Конфиг AntiZapret → OpenVPN (панель)** | Список IP/доменов для `.ovpn` **активного VPN-узла** (тот же список, что на вкладке Прокси) |
| **NOC Мониторинг → Подключения** | Домашний IP / пометка «через прокси» |
| `backend/.env` / модули | Можно задать `FEATURE_PROXY_NODES_ENABLED` (обычно достаточно UI) |

### На зарубежном VPN-сервере

| Место | Что |
|-------|-----|
| AntiZapret + OpenVPN/WG | Реальные сессии клиентов |
| `node_agent` (порт **9100**) | Связь панели с VPN-узлом |
| `allow-ips.txt` | IP, с которых VPN принимает подключения (туда должен попасть IP RU-прокси) |
| `.ovpn` на диске | После `setup.sh` снова «сток»; multi-`remote` снова появится при **пересборке профилей** из панели или при **скачивании** (панель всегда патчит выдачу из БД) |

### На российском прокси (RU VPS)

| Место | Что |
|-------|-----|
| AntiZapret `proxy.sh` | Сам прокси (ставите **вручную**) |
| `proxy_agent` + systemd `adminpanelaz-proxy` | Агент панели, порт **9101** |
| `backend/proxy_agent.env` | Ключ API, порт — создаёт `install.sh --proxy-only` |
| iptables (nat) | Куда реально уходит трафик (`DESTINATION`); панель меняет правила через агент |

Схема потоков:

```text
Клиент ──► RU-прокси (proxy.sh) ──► VPN DESTINATION
                ▲
                │ proxy_agent :9101
                │
             Панель
                │
                ▼ node_agent :9100
             VPN-узел (сессии, allow-ips, конфиги)
```

## Быстрый старт (чеклист)

1. На **RU VPS** установите прокси по [инструкции AntiZapret](https://github.com/GubernievS/AntiZapret-VPN#настроить-прокси-сервер) (`proxy.sh`). Запомните публичный IP прокси и `DESTINATION` (IP зарубежного VPN).
2. На том же RU склонируйте (или скопируйте) репозиторий AdminPanelAZ — обычно в `/opt/AdminPanelAZ` (см. [proxy-agent.md](proxy-agent.md#репозиторий-на-ru-vps)).
3. Поставьте **proxy_agent** одной командой:

```bash
cd /opt/AdminPanelAZ && sudo ./install.sh --proxy-only --with-systemd -y
```

   (или мастер: пункт «Только proxy_agent»). Сохраните показанный API-ключ. Подробнее: [proxy-agent.md](proxy-agent.md).
4. Откройте порт **9101** с IP панели.
5. В панели: **Настройки → Модули** → включите **Прокси-узлы** → сохраните.
6. **Узлы → Добавить узел** → тип **Прокси**, хост = IP RU, порт **9101**, ключ из установки → **Проверить**.
7. В карточке прокси (на **Узлы** или **Конфигурация → Прокси**): **Статус** («proxy.sh обнаружен»), при необходимости **DESTINATION IP** → **Сохранить**.
8. На **VPN-узле**: **Конфиг AntiZapret → OpenVPN (панель)** или **Конфигурация → Прокси** — прокси обычно **первым**, затем зарубежные серверы → **Сохранить адреса**.
9. **«Добавить первый адрес в allow-ips»** (или вручную в `allow-ips.txt` на VPN) и примените конфиг.
10. Пересоберите профили или выдайте клиенту свежий `.ovpn`.
11. В **NOC → Подключения** при живых mappings — домашний IP и бейдж «через прокси».

## Модуль «Прокси-узлы»

| Состояние | Что видно |
|-----------|-----------|
| **Выкл.** (по умолчанию) | Нет типа «Прокси» при добавлении узла, нет карточки proxy_agent, склейка IP в NOC **не** выполняется |
| **Вкл.** | Можно создавать прокси-узлы, смотреть статус/DESTINATION, NOC может восстанавливать домашний IP |

Включение: **Настройки → Модули** — [moduli.md](nastrojki/moduli.md).

## Работа с прокси-узлом в UI

### Добавить

1. Модуль включён.
2. **Узлы → Добавить узел**.
3. Тип: **Прокси (proxy_agent)**.
4. Имя, адрес RU, порт **9101**, API-ключ из `proxy_agent.env`.
5. **Привязан к** (опционально) — HA-группа или отдельный VPN-сервер, чтобы в списке было видно «чей» это прокси.
6. Сохранить → **Проверить**.

В таблице у строки будет бейдж **Прокси** и подпись привязки (например `→ HA «Europe»` или `→ vpn-eu-1`). Кнопки вроде «Активировать» для VPN к прокси **не** относятся.

### Статус и DESTINATION

Раскройте / откройте карточку прокси-узла на **Узлы** или откройте **Конфигурация → Прокси** — блок **Прокси (proxy_agent)**:

| Элемент | Смысл |
|---------|--------|
| **Привязан к** | Организационная связь с HA-группой или VPN-сервером (не меняет DESTINATION) |
| **Статус** | Обновить данные с агента; бейдж «proxy.sh обнаружен» / «не найден» |
| **DESTINATION IP** | Куда прокси шлёт трафик (IP зарубежного VPN) |
| **Сохранить** | Переписать DNAT/SNAT в iptables на RU **через агент**, без запуска `proxy.sh` |
| Кэш панели | Последний известный DESTINATION, сохранённый у узла в БД |

Если статус говорит, что `proxy.sh` не найден — сначала поставьте прокси по AntiZapret, потом снова **Статус**.

### Что прокси-узел не умеет

- Не хранит клиентов и не раздаёт `.ovpn` / WG.
- Не участвует в HA Sync Group как VPN.
- Не заменяет список **Адреса подключения** на VPN-узле.
- Не ставит `proxy.sh`.

## Адреса подключения на VPN (связь с прокси)

Список задаётся **на VPN-узле**, не на прокси-узле (UI: **Конфиг AntiZapret → OpenVPN (панель)** или **Конфигурация → Прокси**).

Типичный порядок для России:

1. IP или домен **RU-прокси**
2. Основной зарубежный сервер
3. (опционально) запасные зарубежные

Разный порядок на разных VPN-узлах — нормальная практика (см. примеры в [antizapret-config.md](antizapret-config.md#несколько-адресов-подключения)).

| Действие | Результат |
|----------|-----------|
| **Сохранить адреса** | Список в БД панели; непустой список best-effort пишет первый адрес в `OPENVPN_HOST` на узле |
| **Скачать / QR / Telegram / публичная ссылка** | В `.ovpn` подставляются все `remote`; у WG в Endpoint — **первый** адрес |
| **Пересобрать профили** из панели | Multi-`remote` ещё и на **диске** VPN |
| **Добавить первый адрес в allow-ips** | Первый адрес списка → `allow-ips.txt` на этом VPN (+ apply) |

Без IP прокси в `allow-ips.txt` зарубежный сервер может **отклонять** подключения, пришедшие с прокси.

После `setup.sh` на VPN шаблоны на диске снова стоковые — список в панели **не** пропадает; снова запишите на диск пересборкой или выдайте конфиг клиенту.

## NOC: домашний IP за прокси

Условие: модуль **Прокси-узлы** включён, в панели есть прокси-узел с **IPv4-адресом** в поле хоста, `proxy_agent` отдаёт mappings.

| Ситуация | Что в списке подключений |
|----------|---------------------------|
| Сессия пришла с IP прокси, порт совпал с маппингом | Показан **домашний IP**, geo по нему, бейдж «через прокси» |
| IP прокси, но маппинга нет / агент недоступен | Остаётся IP прокси, бейдж «через прокси · IP не восстановлен» |
| Модуль выкл. или IP не из списка прокси | Как раньше, без бейджа |

Учёт трафика и Telegram-сводки **не** меняются этой склейкой. Подробнее: [noc-monitoring.md](noc-monitoring.md#подключения-через-прокси-узел).

Mappings живут в conntrack на RU и забираются агентом; кэш на панели ~45 секунд.

## Несколько прокси и несколько VPN

- Один RU-прокси в AntiZapret обычно смотрит на **один** DESTINATION (один зарубежный VPN). Чтобы слать на другой VPN — смените DESTINATION в карточке прокси (или поднимите второй RU).
- Несколько VPN-узлов в панели: у каждого свой список **Адреса подключения** и свой `allow-ips.txt`.
- Несколько прокси-узлов: в NOC матч идёт по IP прокси и порту **этого** прокси (порты разных прокси не смешиваются).

## Частые вопросы

**Почему нет кнопки «Установить proxy.sh»?**  
Намеренно. Панель только мониторит и меняет DESTINATION через `proxy_agent`.

**Прокси-узел offline / ошибка SSL**  
Часто несовпадение HTTP и HTTPS (mTLS). Смотрите текст ошибки в карточке и [proxy-agent.md](proxy-agent.md#mtls-опционально). Проверьте firewall на **9101** и API-ключ.

**Клиент подключается, но в NOC виден только IP прокси**  
Проверьте: модуль вкл., хост прокси-узла — именно **IPv4** прокси (не домен), агент online, сессия ещё жива (маппинг в conntrack). Бейдж «IP не восстановлен» как раз про это.

**Сменил DESTINATION — клиенты отвалились**  
Они всё ещё смотрят на старый VPN в своём туннеле/ожиданиях. Новый DESTINATION должен быть тем VPN, куда вы хотите слать трафик; профили с remote на другой сервер сами по себе DESTINATION не меняют.

**Трафик в панели «не с прокси»**  
Нормально: сессия учитывается на **VPN-узле**. Прокси — транспорт до VPN.

**Можно ли указать домен вместо IP у прокси-узла?**  
Для карточки/health — да, если резолвится. Для склейки NOC нужен **IPv4** в поле хоста (или совпадение с IP в сессии); домен в match-набор не попадает.

**Что такое `linked_vpn_node_id`?**  
Опциональная **привязка прокси к VPN-узлу** (или к HA-группе через primary-узел группы). В UI: поле **«Привязан к»** при создании/редактировании прокси и в карточке прокси (Узлы / Конфигурация → Прокси). На DESTINATION и маршрутизацию не влияет — только чтобы при нескольких прокси было видно, что к чему относится.

---

## Будьте осторожны

- Смена DESTINATION на «чужой» IP отправит чужой трафик не туда — проверяйте адрес.
- **Удалить прокси-узел** в панели не удаляет `proxy.sh` и агент на RU.
- Не путайте порт **9101** (прокси) и **9100** (VPN node agent).
- Первый адрес в списке remote часто попадает в `OPENVPN_HOST` и в allow-ips — осознанно ставьте прокси первым, если так задумано.
