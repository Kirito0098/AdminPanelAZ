# Разделы панели

## Зачем этот раздел

Здесь **включают и выключают разделы** бокового меню и фоновые задачи панели. Также выбирают **сценарий** — готовый набор разделов и фоновых задач.

## Кто может пользоваться

Только **администратор**.

## Как открыть

**Настройки** → **Разделы панели**.

---

## Сценарии

Мастер установки спрашивает **Домашняя** (по умолчанию) или **Коммерческая**. Установка без вопросов (`--non-interactive`, например из CI) ставит **Только панель**; `-y` в терминале проходит мастер с ответами по умолчанию, то есть «Домашняя». Сценарий «Только панель» в мастере не предлагается — это технический пресет для слабых VPS, переключается здесь, в UI.

Сценарий меняет **модули и фоновые задачи панели**, а не объём RAM VPN на сервере.

| Сценарий | Когда использовать |
|---------|-------------------|
| **🖥 Только панель** | Панель отдельно от VPN: минимум фоновых задач и опроса узлов |
| **🏠 Домашнее** | Один сервер для себя и семьи: мониторинг и узлы без коммерческих модулей |
| **💼 Коммерческое** | Раздача доступа абонентам: provisioning, портал, unlock-коды, отчёты (**дефолт install**) |

Сценарий **не применяется сразу**: панель показывает diff («Включится: …, Выключится: …») и меняет переключатели только после подтверждения. В «Коммерческом» семь модулей ядра раздачи доступа заблокированы от выключения; снять замки можно кнопкой **Снять ограничения** — сценарий станет **Кастомный**. «Коммерческое» также ставит удержание конфигов после истечения доступа 3 мес., остальные сценарии — 0 (выключено).

Если модули не совпадают ни с одним сценарием, в плашке показывается **Кастомный** с кнопкой **Сбросить к пресету**.

На карточке **текущего** сценария — замер стека «панель + VPN на этом сервере» (MB). Пример для **Коммерческого**: ≈**411 MB** (358+53); среднее за 7 дней ~**148 MB**. «Домашнее» и «Только панель» обычно дают **меньше RAM панели**, VPN на хосте тот же.

После смены сценария **перезапустите панель** — появится подсказка на странице.

На сервере:
```bash
sudo systemctl restart adminpanelaz
```

Модуль **Telegram** после install включён (`FEATURE_TELEGRAM_ENABLED=true`) — раздел виден в меню; bot token задаётся на странице Telegram, не в установщике.

## Пошаговые сценарии

### Отключить ненужный раздел меню

1. Откройте **Разделы панели**
2. Найдите модуль (например, AZ-WARP, Telegram, Журналы)
3. Выключите переключатель
4. **Сохраните**
5. Раздел исчезнет из меню у всех пользователей

### Переключить на облегчённый режим (только панель, 1 GB)

1. Выберите сценарий **Только панель**
2. Нажмите **Применить сценарий**
3. Перезапустите панель
4. Отключите лишние модули вручную, если всё ещё тяжело

### Включить модуль обратно

1. Включите переключатель нужного модуля
2. Сохраните
3. При необходимости перезапустите панель

## Примеры модулей

| Модуль | Что даёт |
|--------|----------|
| NOC / logs_dashboard | NOC Мониторинг |
| traffic_sync | Мониторинг трафика |
| routing | Маршрутизация, CIDR |
| antizapret_config | Конфиг AntiZapret |
| warper | AZ-WARP |
| awg2 | AZ-AWG2 (AmneziaWG 2.0); см. [awg2](../awg2.md) |
| telegram | Раздел Telegram |
| edit_files | Редактор файлов |
| server_monitor | Страница «Сервер» |
| action_logs | Журнал действий администраторов |
| proxy_nodes | Прокси-узлы на странице **Узлы** (**default off**); см. [proxy-nodes](../proxy-nodes.md), [uzly](../uzly.md), [proxy-agent](../proxy-agent.md) |

## Частые вопросы

**Выключил модуль — данные пропали?**  
Нет, данные в базе остаются. Раздел просто скрыт из меню.

**Панель тормозит после включения «Коммерческого»**  
Серверу может не хватать RAM. Переключитесь на **Домашнее** или **Только панель**.

**Нужен ли перезапуск после каждого переключателя?**  
Не всегда, но после смены **сценария** — обязательно.

---

## Будьте осторожны

- Отключение **traffic_sync** или **node_health** ухудшит мониторинг
- **Коммерческое** на слабом сервере может привести к нехватке памяти и падению панели
