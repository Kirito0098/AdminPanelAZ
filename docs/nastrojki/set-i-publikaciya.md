# Адрес сайта и HTTPS

## Зачем этот раздел

Настройка **адреса панели в интернете**: домен, HTTPS, прокси-сервер (Nginx). Без HTTPS многие функции (Telegram Mini App) не работают.

## Кто может пользоваться

Только **администратор**.

## Как открыть

**Настройки** → **Адрес сайта и HTTPS**.

---

## Пошаговые сценарии

### Настроить HTTPS с Let's Encrypt

1. Убедитесь, что домен указывает на ваш сервер (A-запись)
2. Откройте **Адрес сайта и HTTPS**
3. Запустите мастер HTTPS / Nginx
4. Укажите домен и email для сертификата
5. Дождитесь завершения — панель будет доступна по `https://ваш-домен`

Порты **80** и **443** должны быть открыты на сервере.

Поля формы проверяются до любых изменений: домен — имя вида `panel.example.com` или IPv4 (порт через `:` допустим), email — обычный адрес, пути к своему сертификату и ключу — абсолютные, без пробелов и спецсимволов. Иначе панель отклоняет запрос (`422`) и ничего не меняет.

### Доступ по IP сервера закрыт (Nginx)

За Nginx панель открывается только по своему домену. Вместе с vhost панели ставится сервер по умолчанию `sites-available/00-adminpanelaz-default-deny`: запрос по голому IP или к чужому имени на HTTP-порту закрывается без ответа (`444`), на HTTPS-порту отклоняется TLS-рукопожатие (`ssl_reject_handshake`, nginx ≥ 1.19.4; на старом nginx — свой самоподписанный сертификат и `444`). Браузер покажет ошибку соединения, а не страницу входа.

Сервер по умолчанию не ставится на порт, если:
- на нём уже есть любой `default_server`;
- первым на порту объявлен чужой сайт — по IP и дальше отвечает он;
- это HTTPS-порт, а в `server_name` панели или другого сайта на нём указан IP (клиент по IP не передаёт SNI).

При встраивании панели подпутём в чужой сайт сервер по умолчанию не ставится — что отвечает по IP, решает ваш сайт. В режиме `http_direct` (панель на `IP:8000`) это не действует.

**Свой reverse proxy перед сервером** (например, nginx на хосте перед виртуальной машиной с панелью). Если он подключается к серверу по IP, сервер по умолчанию отклонит и его, и панель через прокси перестанет открываться. Настройте в блоке прокси с `proxy_pass` передачу домена панели: `proxy_ssl_server_name on;`, `proxy_ssl_name <домен панели>;`, `proxy_set_header Host <домен панели>;`. Если прокси менять не хотите, задайте `NGINX_DEFAULT_DENY=0` в `backend/.env`: сервер по умолчанию не ставят ни публикация, ни `nginx-repair.sh`, ни переключение режима Cloudflare, а `sudo ./scripts/nginx-default-deny.sh --apply` убирает уже поставленный ([diagnostika.md](diagnostika.md#вернуть-доступ-по-ip)).

На установках, опубликованных до 2.26.0, сервера по умолчанию нет, пока его не поставить: **Настройки** → **Проверка работы** → проверка **Доступ к панели по IP сервера** → **Закрыть доступ по IP** ([diagnostika.md](diagnostika.md#закрыть-доступ-к-панели-по-ip-сервера)). Кнопка ставит только сервер по умолчанию и перечитывает nginx (`reload`), vhost панели и `backend/.env` не трогает. Из SSH то же — `sudo ./scripts/nginx-default-deny.sh --apply`. Сервер по умолчанию ставит и любая перегенерация nginx — см. [После обновления до 2.26.0](#после-обновления-до-2260).

### Не используйте домен AntiZapret для панели

В `/root/antizapret/setup` заданы `OPENVPN_HOST` и `WIREGUARD_HOST` — это адреса в клиентских конфигах VPN. **Домен панели должен быть другим.**

Если совпадут (например оба `vpn.example.com`), через конфиг AntiZapret этот хост уходит в туннель, и локальная панель перестаёт открываться. Обычный VPN при этом может работать — отсюда путаница.

Правильно: `vpn.example.com` для AZ, `panel.example.com` (или другой поддомен) для панели. Панель запретит совпадение при публикации, в скриптах nginx и при сохранении хостов AZ.

**Несколько A-записей на один домен — нормально и рекомендуется.**  
У своего DNS (регистратор, Cloudflare и т.п.) на **один** hostname можно повесить несколько A-записей на разные IP серверов. Так делают для VPN-домена при двух узлах (HA): клиент получает оба адреса. Это не мешает завести **отдельный** hostname для панели (`panel.…`) со своими A-записями.

### DuckDNS ([duckdns.org](https://www.duckdns.org/))

Если своего домена нет — бесплатный [DuckDNS](https://www.duckdns.org/):

1. Зайдите на [https://www.duckdns.org/](https://www.duckdns.org/) и войдите (Google / GitHub / Reddit и т.д.).
2. Создайте **два** имени (на бесплатном аккаунте обычно до **5** доменов), например:
   - `myvpn` → `myvpn.duckdns.org` — для AntiZapret (`OPENVPN_HOST` / `WIREGUARD_HOST`)
   - `mypanel` → `mypanel.duckdns.org` — для панели
3. Скопируйте **token** со страницы DuckDNS (один на аккаунт).
4. В панели: **Настройки → Адрес сайта и HTTPS** → блок **Динамический DNS** → DuckDNS → поддомен `mypanel` + token → сохраните и включите автообновление IP.
5. В мастере публикации укажите `mypanel.duckdns.org` (не `myvpn`).

У DuckDNS у каждого имени обычно **один** текущий IP (обновляется их API). Несколько A-записей на одно duckdns-имя, как у «обычного» DNS, так не настраивают — для VPN и панели нужны **разные** имена DuckDNS. Для HA с failover удобнее свой домен с несколькими A-записями или DNS с health-check.

### Публикация по подпути на общем домене

Если на одном домене уже работают другие проекты (например `https://example.com/monitor`), панель можно опубликовать по отдельному пути:

**При установке:** панель ставится в HTTP; подпуть задайте позже в UI (**Настройки → Адрес сайта и HTTPS**).

**Через UI:**

1. Откройте **Адрес сайта и HTTPS** → мастер настройки
2. Выберите режим **Nginx + Let's Encrypt** (или другой `nginx_*`)
3. Укажите домен и в поле **Путь доступа** — например `/panel`
4. Если на домене уже есть чужой nginx vhost — включите **Автоматически добавить include** или вручную добавьте `include snippets/adminpanelaz-*.conf;` в свой `server { }`
5. После применения панель откроется по `https://ваш-домен/panel/`

Переменная в `.env`: `ACCESS_PATH=/panel`. Это **дополнительная** мера скрытия URL, не замена 2FA и сильного пароля.

При смене пути обновите в BotFather URL Mini App и webhook Telegram (`/panel/api/tg-mini`, `/panel/api/telegram/webhook/...`).

Если домен панели за Cloudflare в режиме **Proxied** (orange-cloud), откройте
**Настройки → Адрес сайта и HTTPS → Cloudflare** (переключатель proxy-mode,
автообновление CIDR, кнопка «Обновить сейчас», статус последнего обновления).
Без Cloudflare proxy-mode можно выключить; за orange-cloud при выключенном режиме
Telegram webhook не увидит IP Telegram — см. [`docs/Telegram.md`](../Telegram.md#telegram-бот-не-отвечает-за-cloudflare-proxy--orange-cloud)
(«Telegram-бот не отвечает за Cloudflare»).
Опционально включите „Доступ только через Cloudflare“, чтобы закрыть прямой доступ к origin
(нужен загруженный список IP Cloudflare — иначе «Нет валидного списка IP Cloudflare. Нажмите «Обновить сейчас».»).

Переключатели **Cloudflare proxy-mode** и **Доступ только через Cloudflare** сначала спрашивают
подтверждение («Включить Cloudflare proxy-mode?», «Включить доступ только через Cloudflare?» и т.п.
с описанием последствий), затем панель перегенерирует nginx (`nginx-repair.sh --no-panel-restart`)
и перезапускает nginx. Сама панель не перезапускается; возможен краткий обрыв HTTP-соединений.
Выключение proxy-mode выключает и „Доступ только через Cloudflare“.

> **Осторожно с общим доменом.** Переключатели перестраивают nginx так же, как `nginx-repair.sh`:
> все vhost домена панели удаляются (копии — в `/etc/nginx/backups`) и ставится выделенный vhost панели.
> Если панель встроена подпутём в чужой сайт (StatusOpenVPN и т.п.), этот сайт перестанет открываться.

### Совместно со StatusOpenVPN на одном домене

[StatusOpenVPN](https://github.com/TheMurmabis/StatusOpenVPN) занимает `https://ваш-домен/status/`. Если оба сервиса поставят **отдельный** nginx-сайт на один домен — конфиги конфликтуют. Поэтому nginx-сайт на домене должен быть один, а второй сервис встраивается в него.

| Способ | Панель | StatusOpenVPN | Чей nginx-сайт |
|--------|--------|---------------|----------------|
| [1. Панель внутри сайта Status](#способ-1-панель-внутри-сайта-status-через-ui-рекомендуется) — через UI, рекомендуется | `https://ваш-домен/panel/` | `https://ваш-домен/status/` | StatusOpenVPN |
| [2. Status внутри сайта панели](#способ-2-status-внутри-сайта-панели-вручную) — вручную | `https://ваш-домен/` | `https://ваш-домен/status/` | AdminPanelAZ |

#### Способ 1: панель внутри сайта Status (через UI, рекомендуется)

1. Сначала установите StatusOpenVPN и проверьте `https://ваш-домен/status/`
2. Установите панель: `sudo ./install.sh` (откроется по `http://IP:порт/`)
3. **Настройки → Адрес сайта и HTTPS** → **Через Nginx** → **Let's Encrypt** → тот же домен → подпуть `panel` → **Интегрировать с StatusOpenVPN** → **Применить**
4. Откройте `https://ваш-домен/panel/`

Панель добавит `include` только в активный vhost Status (`sites-enabled`), с бэкапом, не трогая блок `/status/`.

Подпуть можно выбрать и **без** Status: корень / `/panel` / свой сегмент.

**Проверка**

1. `https://ваш-домен/status/` — Status работает
2. `https://ваш-домен/panel/` — вход в панель
3. Лучше проверить с телефона через мобильный интернет

**Важно**

- В этом способе подпуть **обязателен** — без него собственный nginx-сайт панели конфликтует со Status

#### Способ 2: Status внутри сайта панели (вручную)

Подходит, если панель уже опубликована на корне домена через **Настройки → Адрес сайта и HTTPS** (Nginx + Let's Encrypt) и переносить её на подпуть не хочется. Status тогда подключается блоком `location /status/` в nginx-сайт панели.

1. Установите StatusOpenVPN **без его nginx**: на вопрос `Do you want to enable HTTPS? (y/N)` ответьте `N`, иначе Status создаст второй сайт на том же домене. Запомните порт Status (по умолчанию `1234`). Если Status уже настроил nginx на этом домене — используйте способ 1.
2. Откройте nginx-сайт панели. Файл называется по домену, точки заменены на `_`:

   ```bash
   sudo nano /etc/nginx/sites-available/example_com
   ```

3. В блоке `server { listen 443 ... }`, рядом с `location / {`, добавьте (вместо `<порт>` — порт Status):

   ```nginx
   location /status/ {
       proxy_pass http://127.0.0.1:<порт>;
       client_max_body_size 512m;

       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto https;
       proxy_set_header X-Script-Name /status;

       proxy_redirect off;
   }
   ```

   Если в `location /` вашего файла есть строки `include snippets/cloudflare-realip.conf;` и `include snippets/cloudflare-origin-lock.conf;` (включён режим Cloudflare), добавьте их и в начало блока `/status/`: тогда Status увидит настоящие IP клиентов и тоже будет закрыт от прямых обращений к IP сервера.

4. Проверьте конфиг и примените:

   ```bash
   sudo nginx -t && sudo systemctl reload nginx
   ```

5. Откройте `https://ваш-домен/status/` (Status) и `https://ваш-домен/` (панель).

**Важно**

- Блок пропадает, когда панель заново записывает свой nginx-сайт: **Настройки → Адрес сайта и HTTPS → Применить**, `sudo ./scripts/nginx-repair.sh` (и пункт «Диагностика» в меню `adminpanel-menu.sh`), переустановка через `install.sh`. После этого добавьте блок снова. Обычное обновление панели, переключение Cloudflare и «Закрыть доступ по IP» сайт не переписывают.
- С этим блоком мастер **Адрес сайта и HTTPS** принимает сайт панели за сайт StatusOpenVPN и может предложить **Интегрировать с StatusOpenVPN**. Не включайте интеграцию, пока пользуетесь способом 2: она рассчитана на сайт, который создал сам Status (способ 1).

#### Для обоих способов

- Не удаляйте Status через его `uninstall` после интеграции — часто ломает общий nginx и доступ к панели

#### Если панель пропала после удаления Status

Через веб уже не зайти. Подключитесь к серверу по SSH:

```bash
cd /opt/AdminPanelAZ
sudo ./scripts/nginx-repair.sh
```

Скрипт восстановит nginx для панели. После этого снова откройте панель в браузере и при необходимости настройте публикацию заново. См. также [diagnostika.md](diagnostika.md).

Если пользуетесь Telegram Mini App — после настройки обновите ссылки в BotFather на адрес с `/panel/`.

### Использовать бесплатный DDNS (DuckDNS, No-IP)

Если нет своего домена — в этом же разделе (**Адрес сайта и HTTPS**) откройте блок **Динамический DNS**.

**DuckDNS** — пошагово: [отдельный раздел выше](#duckdns-duckdnsorg). Кратко: два имени на [duckdns.org](https://www.duckdns.org/) (VPN и панель), в DDNS панели указывайте **панельный** поддомен.

**No-IP** и др.:

1. Выберите провайдера и введите данные (hostname / логин / пароль).
2. Включите автообновление IP (timer каждые 5 мин) или нажмите «Обновить IP сейчас».
3. Укажите полученный FQDN в поле домена мастера публикации и настройте HTTPS.

| Сервис | Пример адреса |
|--------|----------------|
| DuckDNS | `mypanel.duckdns.org` (отдельно от VPN-имени) |
| No-IP | `myvpn.ddns.net` |

CLI fallback: `sudo ./scripts/ddns-update.sh update` · `status` · `install-timer`.  
Конфиг: `/etc/adminpanelaz/ddns.env`.

### После обновления до 2.26.0

- **Доступ по IP сервера.** Обновление из интерфейса nginx не перегенерирует — откройте **Настройки** → **Проверка работы** → **Закрыть доступ по IP** ([diagnostika.md](diagnostika.md#закрыть-доступ-к-панели-по-ip-сервера)). Кнопка ставит только сервер по умолчанию и безопасна и для панели, встроенной подпутём в чужой сайт (там она просто сообщит, что закрывать нечего).
- **Nginx.** Перегенерируйте конфиг: `sudo ./scripts/nginx-repair.sh` (или переключите Cloudflare proxy-mode в настройках). Это закрывает доступ к панели по IP сервера и включает реальный IP клиента за Cloudflare. Если панель встроена подпутём в чужой сайт на том же домене, `nginx-repair.sh` не запускайте — он заменит чужой vhost выделенным vhost панели; вместо этого опубликуйте панель заново через мастер.
- **Подпуть на домене с чужим сайтом, поставленный `install.sh`** (режим nginx и подпуть заданы переменными `WIZ_NGINX_MODE` / `WIZ_ACCESS_PATH`): установщик ставил отдельный vhost панели вместо встраивания в чужой сайт, и один из двух сайтов переставал открываться. Опубликуйте панель с подпутём ещё раз — в **Адрес сайта и HTTPS** или через `nginx-setup.sh`.
- **Прямая публикация без Nginx** (`http_direct` или `uvicorn_*`, uvicorn слушает `0.0.0.0`): до 2.26.0 в этих режимах можно было без входа скачать файлы сервера, включая `backend/.env` с `SECRET_KEY`. Смените `SECRET_KEY` мастером ротации — [bezopasnost.md](bezopasnost.md). Ротация завершает сессии всех пользователей.
- **Свой прокси перед панелью не на этом сервере.** Добавьте его адрес в `TRUSTED_PROXY_IPS` (по умолчанию `127.0.0.1`), иначе панель видит адрес прокси вместо адреса клиента, а Telegram webhook отвечает `403` — [bezopasnost.md](bezopasnost.md#trusted_proxy_ips). `nginx-repair.sh`, публикация через Nginx и переключатели Cloudflare записывают в `.env` `TRUSTED_PROXY_IPS=127.0.0.1` — после них верните свой адрес.

### Проверить, что панель доступна извне

1. Откройте адрес панели с телефона **без Wi‑Fi** (через мобильный интернет)
2. Должна открыться страница входа по HTTPS
3. За Nginx откройте `http://IP-сервера` и `https://IP-сервера` — страницы входа быть не должно, только ошибка соединения. Если панель открывается — нажмите **Закрыть доступ по IP** в **Настройки** → **Проверка работы** (или `sudo ./scripts/nginx-default-deny.sh --apply`) и проверьте исключения в разделе [Доступ по IP сервера закрыт](#доступ-по-ip-сервера-закрыт-nginx)

## Частые вопросы

**Панель не открывается через конфиг AntiZapret, а через обычный VPN — да**  
Скорее всего домен панели совпадает с `OPENVPN_HOST` / `WIREGUARD_HOST`. Задайте отдельный домен панели — см. [Не используйте домен AntiZapret](#не-используйте-домен-antizapret-для-панели).

**Telegram Mini App не открывается**  
Нужен публичный **HTTPS** с нормальным сертификатом. HTTP и самоподписанный сертификат не подходят — см. [Telegram.md](../Telegram.md).

**Сертификат истёк**  
Запустите обновление сертификата в этом разделе или на сервере: `sudo ./scripts/nginx-setup.sh`

**Панель открывается только по IP:8000**  
Это нормальный режим сразу после установки (`http_direct`). Для домена и HTTPS настройте **Адрес сайта и HTTPS**.

**Вылетает из панели при смене вкладки (HTTP)**  
На чистом HTTP refresh-cookie больше не ставится с флагом Secure. После обновления панели один раз войдите снова. Если всё ещё вылетает — в `.env` должно быть `REFRESH_TOKEN_COOKIE_SECURE=false` при `PUBLISH_MODE=http_direct`.

**Нужен StatusOpenVPN на том же домене**  
См. [Совместно со StatusOpenVPN](#совместно-со-statusopenvpn-на-одном-домене): только через UI после `install.sh` (**Настройки → Адрес сайта и HTTPS**).

**После удаления Status пропала панель**  
Через SSH: `sudo ./scripts/nginx-repair.sh` — [diagnostika.md](diagnostika.md).

## Будьте осторожны

- Неверная настройка Nginx может **полностью закрыть** доступ к панели — держите SSH-доступ к серверу
- Не публикуйте панель на том же домене, что `OPENVPN_HOST` / `WIREGUARD_HOST` AntiZapret
- На одном домене со StatusOpenVPN не публикуйте панель отдельным nginx-сайтом на корень — используйте подпуть и интеграцию
- При встраивании в чужой сайт не запускайте `nginx-repair.sh` и не переключайте Cloudflare proxy-mode — оба удаляют vhost домена и ставят выделенный vhost панели
- Не публикуйте панель в интернет без **2FA** и надёжного пароля — [profil.md](profil.md), [bezopasnost.md](bezopasnost.md)
