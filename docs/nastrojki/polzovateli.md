# Пользователи

## Зачем этот раздел

Здесь создают **учётные записи** для входа в панель и назначают **роли**: кто полный администратор, кто работает со своими VPN-конфигами (с квотой, правом создавать и доп. доступом к чужим клиентам).

## Кто может пользоваться

Только **администратор**.

## Как открыть

**Настройки** → **Пользователи**.

---

## Роли простыми словами

| Роль | Что может |
|------|-----------|
| **Администратор** | Всё: клиенты, узлы, настройки, бэкапы |
| **Пользователь** | Свои VPN-конфиги; скачивание и QR; создание — если разрешил админ; чужие клиенты — только из белого списка (просмотр/скачивание) |

Роли «Только просмотр» / «Наблюдатель» больше нет: тот же сценарий собирается у **Пользователя** (создание выкл. + доп. доступ к клиентам).

---

## Пошаговые сценарии

### Создать пользователя

1. Нажмите **Добавить**
2. Укажите **Логин** и **Пароль**
3. Выберите **Роль**
4. Нажмите **Создать**
5. При необходимости откройте карточку пользователя (карандаш) и укажите **Telegram ID** — для входа через Telegram и получения конфигов в боте

### Настроить права Пользователя

В карточке пользователя:

1. **Может создавать конфигурации** — вкл/выкл
2. **Квота конфигов** — лимит создаваемых клиентов (если создание включено); пусто — общая квота из [лимитов создания](#лимиты-создания-конфигов)
3. **Доступ до** — срок доступа пользователя (см. ниже)
4. **Доп. доступ к клиентам** — отметьте чужие VPN-клиенты для просмотра и скачивания (без удаления)
5. **Видимость VPN-профилей** — какие типы профилей видны при скачивании/создании
6. Нажмите **Сохранить**

### Лимиты создания конфигов

Секция **Лимиты создания конфигов** под списком пользователей задаёт общие правила для всех обычных пользователей (на администраторов не действуют):

| Поле | По умолчанию | Границы | Что значит |
| ---- | ------------ | ------- | ---------- |
| **Квота конфигов по умолчанию** | 5 | 0–1000 | Максимум VPN-клиентов у пользователя без своей квоты; 0 — без лимита |
| **Созданий за окно** | 3 | 0–100 | Сколько клиентов можно создать подряд; 0 — без ограничения |
| **Окно, минут** | 60 | 1–1440 | За какой период считаются созданные клиенты |

Счётчик созданий хранится в памяти панели: он обнуляется при перезапуске, и при нескольких процессах панели у каждого свой. Те же лимиты есть в Mini App → **Настройки → Лимиты**.

### Задать срок доступа пользователя

1. Откройте карточку пользователя с ролью **Пользователь**
2. В поле **Доступ до** выберите дату (пусто — бессрочно)
3. Нажмите **Сохранить**

При сохранении новой даты этот срок проставляется **всем клиентским профилям** пользователя, где он владелец, — в том числе тем, у которых был свой срок. Если дату не меняли, сохранение других полей сроки профилей не трогает. Срок виден в списке, в колонке **Доступ до**. Как срок работает с порталом и unlock-ключами — [podpiska.md](../podpiska.md).

### Сменить пароль

Свой пароль меняют только в [**Мой профиль**](profil.md#сменить-пароль) — с вводом текущего пароля; запрос на смену своего пароля через изменение пользователя (API) отклоняется с ошибкой 400. Поля для пароля другого пользователя в карточке нет: если пользователь забыл пароль, удалите учётную запись и создайте заново (см. ниже, что при этом происходит).

### Привязать Telegram к пользователю

1. Узнайте Telegram ID пользователя (через бота @userinfobot или команду `/link` в вашем боте)
2. В карточке пользователя укажите **Telegram ID**
3. Сохраните

Подробнее о Telegram: [Telegram.md](../Telegram.md).

### Удалить пользователя

1. Найдите пользователя в списке
2. Нажмите **⋯** → **Удалить**
3. Подтвердите — учётная запись исчезнет, VPN-конфиги на сервере **не удаляются** автоматически

Что происходит при удалении:

- владельцем VPN-конфигов пользователя становится администратор, который его удалил;
- удаляются его passkey, сессии и записи о погашенных unlock-ключах — пользователя с погашенными ключами можно удалить;
- созданные им unlock-ключи, ссылки клиентского портала и портала пользователя продолжают работать.

Удалить себя или последнего администратора нельзя.

### Дать пользователю доступ только к своим конфигам

1. Создайте пользователя с ролью **Пользователь**
2. При создании клиента на странице **Клиенты** укажите этого пользователя **владельцем**

### Дать доступ к чужим конфигам без владения

1. Откройте карточку пользователя
2. В **Доп. доступ к клиентам** отметьте нужные имена
3. При необходимости выключите **Может создавать конфигурации**

## Частые вопросы

**Сколько администраторов можно?**  
Сколько нужно, но для безопасности лучше минимум — один основной и запасной.

**Пользователь видит чужие конфиги?**  
Только если админ добавил их в **Доп. доступ к клиентам**. Удалять чужие нельзя.

**Можно ли сменить роль?**  
Да — отредактируйте пользователя и выберите другую роль.

---

## Будьте осторожны

- Не давайте роль **Администратор** без необходимости
- Удаление пользователя **не отключает** его VPN на сервере — при необходимости заблокируйте клиента отдельно
- Передавайте начальный пароль по защищённому каналу, не в открытом чате
- После обновления панели, если раньше была роль «Только просмотр», выполните повторный вход
