# AZ-AWG2 Wave 4a Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** When `FEATURE_AWG2_ENABLED` and the az-awg2 layer is installed, show AmneziaWG 2.0 peers in NOC monitoring overview, connection-history charts, and Telegram NOC text/PNG — as a third protocol, not merged into WireGuard.

**Architecture:** Reuse `adapter.get_awg2_monitoring()` (already wave 2c). Map clients → `WireGuardPeer`-shaped objects into a new `amneziawg2_peers` field; online via `latest_handshake` + existing 180s helpers. Sample `amneziawg2_count` into `connection_count_samples`. TG NOC reads current/peak AWG2 from those samples (no live adapters; traffic sessions come in 4b).

**Tech Stack:** FastAPI/SQLAlchemy monitoring_overview, connection_history, noc_report(+image), React MonitoringPage/charts, pytest MagicMock.

**Spec:** `docs/superpowers/specs/2026-08-11-az-awg2-noc-traffic-design.md` § Волна 4a  
**Next:** `docs/superpowers/plans/2026-08-11-az-awg2-wave4b.md` (after 4a)  
**Depends on:** waves 1–3c (`get_awg2_monitoring`, `VpnType.amneziawg2`, HA lookup keys)

## Global Constraints

- Spec §4a only — no traffic collector, no traffic limits, no `/awg2` Monitoring tab rewrite
- Third protocol: never put AWG2 into `wireguard_peers` / `protocol_type=wireguard`
- Gate: `FEATURE_AWG2_ENABLED` via `is_awg2_enabled(db)`; per-node skip if not installed / adapter error → empty list, no 500
- Online = handshake age &lt; 180s (`AWG2_ONLINE_WINDOW_S` / existing WG helpers)
- UI label short: **AWG 2.0**; module name remains AZ-AWG2
- Toggle off → hide AWG2 filter/series; API may still return `0`/`[]` defaults
- Skip git commits unless the user explicitly asks
