# Конфиг AntiZapret

## Зачем эта страница

Здесь меняют **основные настройки** VPN-сервера AntiZapret: какие сервисы направлять через VPN, резервные порты, безопасность и параметры WARP.

## Кто может пользоваться

Только **администратор**.

## Как открыть

Боковое меню → **Конфиг AntiZapret**.

Настройки применяются к **активному узлу** — проверьте выбор в шапке.

## Разделы настроек

| Раздел | О чём |
| -------- | ------- |
| **Маршрутизация трафика** | Discord, Cloudflare, Telegram и другие сервисы — через VPN или напрямую |
| **Резервные порты** | Альтернативные порты OpenVPN и WireGuard для обхода блокировок |
| **Cloudflare WARP** | Встроенный WARP AntiZapret-VPN: режимы `ANTIZAPRET_WARP` / `VPN_WARP`, `WARP_PROTECTION`, `WARP_ENDPOINT`, `WARP_MTU`, `DNS_WARP` и `RECONNECT_WARP` (см. ниже; AZ-WARP — [warper.md](warper.md)) |
| **Безопасность сервера** | Защита самого VPN-сервера, включая изоляцию клиентов (`CLIENT_ISOLATION`) и защиту от флуда (`FLOOD_PROTECTION`). Применяется сразу — служба `antizapret` перезапускается |
| **Подсети клиентов** | `ALTERNATIVE_CLIENT_IP` и `ALTERNATIVE_FAKE_IP` — диапазоны адресов клиентов и fake-IP. Меняют адреса у всех клиентов (см. [ниже](#подсети-клиентов-и-fake-ip)) |
| **Адреса подключения** | `OPENVPN_HOST` / `WIREGUARD_HOST` из setup. **Список remote OpenVPN** и **OpenVPN multihome** — вкладка **OpenVPN (панель)** |
| **DNS: ответ на AAAA** | `::` или NODATA на AAAA-запросы для AntiZapret и полного VPN — вкладка **OpenVPN (панель)** (см. [ниже](#dns-ответ-на-aaaa)) |
| **Списки и хосты** | Связь с файлами доменов и IP (подробнее — [edit-files.md](edit-files.md)) |

## Встроенный Cloudflare WARP

Новые версии AntiZapret-VPN хранят режим WARP числом, а не флагом `y/n`:

| Параметр | Значения |
| ---------- | ---------- |
| `ANTIZAPRET_WARP` (antizapret-*) | `1` None — не использовать · `2` All — весь трафик · `3` Domain — домены AntiZapret и списка WARP · `4` Custom — только домены списка WARP (в обоих случаях минус `exclude-warp-hosts.txt`) |
| `VPN_WARP` (vpn-*) | `1` None · `2` All · `3` Custom — только домены `include-warp-hosts.txt` (минус `exclude-warp-hosts.txt`); режим есть в AntiZapret-VPN с 26.10.2026 |
| `WARP_PROTECTION` | `y` — блокировать трафик AntiZapret и полного VPN, если WARP не подключился; `n` — выпускать напрямую |
| `WARP_ENDPOINT` | Свой endpoint WARP в формате `host:port`, по умолчанию `162.159.192.1:500`; пусто — endpoint из API Cloudflare. Действует, пока ключи WARP не заданы в `setup` вручную (AntiZapret генерирует их сам). Применяется сразу — служба `antizapret` перезапускается |
| `WARP_MTU` | MTU интерфейсов встроенного WARP, число от 1280 до 1420 (как в установщике). Пусто — 1280 (так считает сам AntiZapret-VPN). Уменьшайте, если через WARP не открываются часть сайтов или обрываются загрузки. После смены — **Применить (doall.sh)** |
| `DNS_WARP` | `y` — весь исходящий DNS через встроенный WARP (если выбранные резолверы заблокированы у провайдера); `n` — обычный выход. Панель меняет флаг только на новом AntiZapret-VPN: если в `setup` он ещё в виде `1`/`2` (до 26.10.2026) или нет числовых `ANTIZAPRET_WARP`/`VPN_WARP` (старая установка), значение показывается, но запись отклоняется с просьбой обновить AntiZapret-VPN — старый `up.sh` прочитал бы `y` как «выключено» |
| `RECONNECT_WARP` | `y` — при обновлении списков AntiZapret и каждую ночь переподключает встроенный WARP, если сервер работает больше минуты. Помогает, когда WARP «отвалился» и домены ушли напрямую. Применяется через **Применить (doall.sh)** |

**Список WARP** — это ваш `config/include-warp-hosts.txt` плюс STUN/TURN-серверы Cloudflare и Google, которые AntiZapret-VPN добавляет сам (`download/include-warp-hosts.txt`). Свой список и исключения (`exclude-warp-hosts.txt`) правятся в [Редакторе файлов](edit-files.md#warp) → группа **WARP**.

Старый node agent (до 1.11.0) не знает `WARP_MTU` и молча его пропустит. Если вы задали значение, отличное от 1280, панель после сохранения покажет предупреждение — обновите агент на узле и сохраните ещё раз. `WARP_ENDPOINT` и `CLEAR_DNS_CACHE` появились в панели позже: для их записи на узле нужен **node agent 1.18.0**. Если агент старый, панель после сохранения предупредит, что значение не записано.

**Старый формат `y/n`.** Если в `setup` узла ещё `ANTIZAPRET_WARP=y|n` (AntiZapret-VPN до перехода на номера), панель показывает `y` как `2` (All), `n` как `1` (None) и при сохранении пишет обратно `y`/`n`. Режимы `3`/`4` на таком узле сохранить нельзя — панель ответит ошибкой с просьбой обновить AntiZapret-VPN. `WARP_PROTECTION` старые версии игнорируют.

Старый node agent (до 1.11.0) не понимает числовые значения и запишет `n`. Панель после сохранения перечитывает setup и покажет предупреждение — обновите агент на узле и сохраните ещё раз.

Встроенный WARP AntiZapret и AZ-WARP с AZ-WARP 1.5.0 работают вместе; после смены режима и doall.sh нажмите **AZ-WARP → Настройки → Обслуживание → Запустить resync**, чтобы AZ-WARP перестроил правила (подробнее — [warper.md](warper.md)).

## Подсети клиентов и fake-IP

Два флага из `setup` AntiZapret:

| Флаг | Включено | Выключено |
| --- | --- | --- |
| `ALTERNATIVE_CLIENT_IP` | клиенты `172.29.8.x` / `172.28.8.x`, шлюз и DNS `172.29.8.1` | `10.29.8.x` / `10.28.8.x`, DNS `10.29.8.1` |
| `ALTERNATIVE_FAKE_IP` | fake-IP пул `198.18.0.0/15` | `10.30.0.0/15` |

Эти ключи читают только `up.sh`, `parse.sh` и `down.sh` — правила iptables и профили клиентов. Поэтому одной записи в `setup` мало, и панель после **Сохранить** дополнительно:

- переписывает подсети клиентов в `/etc/knot-resolver/kresd.conf` (`view:addr`) и перезапускает `kresd@1/2/3`; если резолвер не поднялся, файл возвращается как был;
- меняет `--fake-cidr` в `/root/antizapret/proxy.py` — иначе resolver продолжал бы выдавать `198.18.*`;
- правит `AZ_SUBNET` / `VPN_SUBNET` / `AZ_DNS` / `VPN_DNS` в `/etc/amnezia/amneziawg/services.env` (интерфейсы AZ-AWG2) и перезапускает `awg-quick@antizapret-awg` и `@vpn-awg`.

Файлы переписываются **до** перезапуска `antizapret`: служба запускает `proxy.py`, поэтому при обратном порядке новый fake-пул заработал бы только при следующем рестарте. В HA с `sync_mode=auto` те же файлы патчатся и на репликах. Для удалённого узла нужен **node agent 1.18.0**; на старом агенте панель предупредит, что подсети не применены, вернёт прежние значения в `setup` и не станет перезапускать `antizapret`.

После смены обязательно **пересоберите профили** («OpenVPN (панель)» → пересоздать профили / `client.sh 7`) и попросите клиентов переподключиться: в уже выданных `.ovpn`, `.conf` и `-am.conf` остались прежние адреса. В **AZ-WARP** нажмите **Запустить resync**.

Два предупреждения:

- обновление AntiZapret скачивает `proxy.py` заново — после него сохраните настройки ещё раз (или `custom-up.sh` повторит правку);
- если в `/root/antizapret/custom-up.sh` есть правила для `172.29` / `198.18` — их нужно поправить под новый режим, панель этот файл не трогает.

## Очистка и исключения списков

**Очистка хостов (`CLEAR_HOSTS`).** С сентября 2026 года AntiZapret-VPN при очистке удаляет не только домены казино и букмекеров, но и **все домены со словами `vpn` и `proxy`**. Фильтр применяется и к вашему `include-hosts.txt`: если нужен такой домен через AntiZapret, выключите очистку в разделе **Очистка списков**.

**Очистка DNS-кеша (`CLEAR_DNS_CACHE`).** С 09.11.2026 `doall.sh` и ночная очистка могут сбрасывать кеш Knot Resolver. Помогает, когда домен уже переехал на новый IP, а клиенты продолжают видеть старый. Применяется через **Применить (doall.sh)**; на более старом AntiZapret-VPN флаг игнорируется.

**Списки облаков.** Флаги `AMAZON_INCLUDE`, `HETZNER_INCLUDE`, `DIGITALOCEAN_INCLUDE`, `OVH_INCLUDE`, `GOOGLE_INCLUDE`, `AKAMAI_INCLUDE` в установщике AntiZapret-VPN больше не спрашиваются, а файлы `download/*-ips.txt` обновляются редко (Amazon — с 2025 года, Google — с февраля 2026). Панель показывает их в карточке **Другие параметры** с этой пометкой: включайте, только если готовы поддерживать список сами.

**Исключения AntiZapret-VPN.** AntiZapret-VPN скачивает свой список исключений всегда, а не только при `ROUTE_ALL=y`: это служебные домены (проверка связи Android, уведомления Google, Sentry и т.п.), которые не нужно пускать через VPN. При `ROUTE_ALL=y` вместо него скачивается список исключений российских зон (`.ru`, `.su`, `.рф` и другие). Ваш `exclude-hosts.txt` в редакторе файлов действует в обоих случаях.

## Ограничение форвардинга

**`forward-ips.txt` и `route-ips.txt` AntiZapret-VPN применяет всегда** (с 28.10.2026): адреса из этих списков разрешены к форвардингу, и правило-разрешение ставится при каждом `up.sh` — независимо от флага. Флаг **`RESTRICT_FORWARD`** (раздел «Безопасность сервера») добавляет запрет: трафик клиентов AntiZapret VPN к адресам вне этих списков блокируется. На узле со старой версией AntiZapret список без флага не действовал, поэтому на такой установке описание в панели относится только к включённому флагу.

**`drop-ips.txt`** (с 27.04.2026) — список IPv4/CIDR, которым **запрещён форвардинг** через AntiZapret VPN и полный VPN. Адрес из этого файла не пройдёт через VPN, даже если попал в `include-ips.txt`, `forward-ips.txt` или списки доменов; удобно, чтобы закрыть подсети Max, VK, Telegram и подобных сервисов. Правится в [Редакторе файлов](edit-files.md#ip-адреса) → группа **IP-адреса**. **`deny-ips.txt`** (с 05.05.2026) блокирует **входящие** подключения с указанных адресов — защита от сканеров; обе настройки требуют обновлённого AntiZapret-VPN.

**Изоляция клиентов** (`CLIENT_ISOLATION`, раздел «Безопасность сервера», по умолчанию включена) блокирует **входящие** соединения с клиентских адресов на сервер и к другим клиентам, кроме DNS (порт 53). С 31.10.2026 AntiZapret больше не запрещает форвардинг между клиентами: изоляция защищает сам сервер и его службы, а не изолирует клиентов друг от друга.

## Защита от флуда

**`FLOOD_PROTECTION`** (раздел «Безопасность сервера») ограничивает активность одного клиентского адреса — не жёстко, но вредонос в сети не разгонится:

- новые соединения — 100 в секунду, всплеск до 1000 (запас восстанавливается за 10 секунд);
- всего соединений — 1000 в любом состоянии;
- отдельный лимит на подключения к локальному DNS.

Флаг читает `up.sh`, поэтому применяется сразу — служба `antizapret` перезапускается (несколько секунд не работает DNS-прокси). На старом AntiZapret-VPN флага нет — обновите базу.

## Как применяются настройки

| Группа | Что происходит после **Сохранить** |
| -------- | ----------------------------------- |
| **Безопасность сервера** (включая защиту от флуда), **резервные порты**, `RESTRICT_FORWARD`, режимы **Cloudflare WARP** (`ANTIZAPRET_WARP`, `VPN_WARP`, `WARP_PROTECTION`, `WARP_ENDPOINT`, `WARP_MTU`) | Панель пишет `setup` и **сама перезапускает службу `antizapret`** — `up.sh` пересобирает iptables и WARP-интерфейсы. Несколько секунд не работает DNS-прокси AntiZapret: клиенты остаются подключены, но новые имена не разрешаются |
| **Маршрутизация трафика**, **AdBlock**, **очистка списков** (включая `CLEAR_DNS_CACHE`), **Cloudflare WARP**: `DNS_WARP` и `RECONNECT_WARP` | Панель пишет `setup`; списки и DNS-кеш пересобирает **Применить (doall.sh)** — `update.sh` + `parse.sh`. `RECONNECT_WARP` срабатывает в этом же проходе |
| **DNS-серверы** | Отдельная карточка на вкладке **OpenVPN (панель)** — правит `kresd.conf` и перезапускает резолверы (см. [ниже](#dns-серверы)) |

В HA-группе с `sync_mode=auto` настройки первой группы применяются и на репликах: панель пишет `setup` и перезапускает `antizapret` на каждой реплике. Если рестарт не удался, настройки уже сохранены, а в ответе будет предупреждение — перезапустите службу вручную.

## Out IP protection

Если в `setup` на узле вручную заданы `ANTIZAPRET_OUT_IP` или `VPN_OUT_IP` (отдельный IP для исходящего трафика VPN), AntiZapret-VPN с сентября 2026 года при старте блокирует **весь входящий трафик на эти адреса** (`iptables -I INPUT 1 -d <IP> -j DROP`). Панель эти параметры не показывает и не меняет. Если панель подключается к node agent узла по такому IP, после перезапуска AntiZapret узел станет недоступен — укажите в **Узлы → Изменить** основной адрес сервера. То же касается SSH и адреса в DNS для клиентов: они должны смотреть на основной IP, а не на OUT IP.

## DNS: ответ на AAAA

AntiZapret-VPN на любой AAAA-запрос (IPv6-адрес) отвечает `::`. Некоторые клиенты считают это настоящим адресом и подключаются сами к себе — например, Spotify через Music Assistant не играет, если `spotify.com` / `scdn.co` добавлены в AntiZapret. Ответ NODATA говорит клиенту, что IPv6-адреса нет, и он идёт по IPv4. Утечек IPv6 это не добавляет: AntiZapret не выдаёт клиентам IPv6.

На вкладке **OpenVPN (панель)** в карточке **DNS: ответ на AAAA** два переключателя для активного узла:

| Переключатель | Файл | Резолвер |
|---------------|------|----------|
| AntiZapret: NODATA вместо `::` | `/etc/knot-resolver/custom.lua` | `kresd@1` |
| Полный VPN: NODATA вместо `::` | `/etc/knot-resolver/custom2.lua` | `kresd@2` |
Третьего резолвера (`kresd@3`, **Proxy DNS**) переключатель не касается: прокси-DNS не подменяет A/AAAA нулями, его файл `custom3.lua` правится в [Редакторе файлов](edit-files.md#dns-knot-resolver).

Действует на всех клиентов (OpenVPN, WireGuard, AmneziaWG). Панель добавляет в конец файла блок между строками `-- [ADMINPANEL-AAAA-NODATA-START]` и `-- [ADMINPANEL-AAAA-NODATA-END]` и перезапускает только нужный резолвер, без doall.sh; если резолвер не поднялся — возвращает прежний файл. Служебные имена (`localhost`, частные и специальные зоны) отвечают как раньше. `setup.sh` сохраняет `custom*.lua`, поэтому настройка переживает переустановку. В HA-группе файл реплицируется на реплики, если включена автосинхронизация файлов (`NODE_SYNC_AUTO_REPLICATE_CONFIG_FILES`, по умолчанию включена). Клиенты и приложения могут помнить прежний ответ до суток — после переключения переподключите VPN или перезапустите приложение. Если блок изменить вручную в Редакторе файлов, переключатель блокируется, пока блок не вернут или не удалят. Нужен node agent 1.11.0.

## DNS-серверы

На вкладке **OpenVPN (панель)** карточка **DNS-серверы** выбирает, какими резолверами AntiZapret разрешает домены:

| Селект | Что настраивает | Значения |
|--------|-----------------|----------|
| **AntiZapret VPN (antizapret-*)** | `local antizapret_dns` в `/etc/knot-resolver/kresd.conf` (`kresd@1`) | 1 MSK-IX + NSDI + BI.ZONE + TransTeleCom (по умолчанию, для РФ) · 2 Cloudflare + Quad9 + ControlD + UltraDNS · 3 Яндекс · 4 Google · 5 AdGuard · 6 GeoHide |
| **Полный VPN (vpn-*)** | `local vpn_dns` (`kresd@2`) | 1 — тот же DNS, что у AntiZapret · 2 Cloudflare/Quad9 (разрешает свой DNS у клиентов vpn-*) |

Список вариантов панель читает из самого `kresd.conf` (функция `upstream()`), а не хранит копию меню установщика. Поэтому на базе до 09.11.2026, где ещё есть Comss, панель покажет 7 вариантов (Comss — 6, GeoHide — 7), а после обновления базы — 6 (GeoHide — 6). Если в `setup` осталось значение, которого установленный резолвер не понимает, панель предупредит и попросит выбрать DNS заново.

`setup.sh` записывает эти два значения в `kresd.conf` через `sed` и при работе их не переприменяет, поэтому панель меняет **сами строки файла** и перезапускает резолверы — одной записи в `setup` было бы недостаточно. Выбор также сохраняется в `setup` (`ANTIZAPRET_DNS`, `VPN_DNS`), чтобы повторный `setup.sh` не сбросил его.

Что происходит при **Применить**:

- строки `local antizapret_dns` / `local vpn_dns` переписываются, остальной `kresd.conf` не меняется;
- перезапускается `kresd@1`; если изменился `vpn_dns` — ещё и `kresd@2`. Несколько секунд клиенты не могут разрешать имена;
- если изменился сам режим полного VPN (`VPN_DNS`), перезапускается `antizapret` — `up.sh` по этому флагу ставит DNAT на `127.2.2.2` и правила блокировки DoT;
- если резолвер не поднялся с новым значением, панель возвращает прежний `kresd.conf` и перезапускает `kresd` обратно, а в ответе показывает ошибку;
- в HA-группе с `sync_mode=auto` выбор применяется и на репликах (best-effort: узел со старым агентом попадёт в предупреждения).

Требуется **node agent 1.15.0**; на старом агенте карточка отвечает «Обновите node agent панели на узле». Клиенты могут помнить прежний ответ до суток — после смены переподключите VPN или перезапустите приложение.

## OpenVPN: профили, логи и состояние установки

На вкладке **OpenVPN (панель)** карточка **«OpenVPN: профили, логи и состояние установки»**.

**Переключатели** (правят те же строки, что `setup.sh`, и перезапускают включённые службы OpenVPN — клиенты переподключатся):

| Переключатель | Что делает | Строки в `server/*.conf` |
| --- | --- | --- |
| **Несколько устройств с одним профилем** | включено — одним `*.ovpn` можно подключиться с нескольких устройств; выключено — новое подключение выбивает предыдущее | `duplicate-cn` / `#duplicate-cn` |
| **Подробные логи и статус OpenVPN** | подробный журнал, файл лога и периодический status (нужны для разбора жалоб и OpenVPN Buffer Guard) | `verb 4`, `log-append`, `status` (раскомментированы/закомментированы) |

Если служба не поднялась после правки, панель возвращает прежние конфиги и перезапускает OpenVPN обратно. Выключенные (disabled) протоколы не трогаются — их конфиги обновятся при следующем включении.

**Только чтение — состояние установки:**

| Что | Откуда берётся |
| --- | --- |
| **MTU OpenVPN / WireGuard** | `tun-mtu` в `server/*.conf` и `MTU =` в `/etc/wireguard/templates/*.conf`; «разнобой» — значения различаются |
| **DCO** | `disable-dco` и набор `data-ciphers`: `on` — только AEAD, `off` — есть `disable-dco` или CBC-шифры |
| **Патч антицензуры OpenVPN** | собранный бинарник `/usr/local/sbin/openvpn` и то, что реально запускает служба (`systemctl show -p ExecStart`). «Собран, но служба запускает системный бинарник» — патч не действует |
| **Протоколы** | `systemctl is-enabled` для `openvpn-server@{antizapret,vpn}-{udp,tcp}` и `wg-quick@{antizapret,vpn}` |
| **Автообновление списков** | `systemctl is-enabled antizapret-update.timer` |

Нужен **node agent 1.16.0**; на старом агенте карточка ответит «Обновите node agent панели на узле». В HA с `sync_mode=auto` переключатели применяются и на репликах (best-effort, ошибки — в предупреждениях).

### MTU

Два **независимых** значения (установщик спрашивает один MTU и ставит оба — здесь можно раздельно):

| Поле | Что меняет |
| --- | --- |
| **OpenVPN** (1280–1420) | `tun-mtu` во всех `openvpn/server/*.conf` |
| **WireGuard** (1280–1420) | `MTU =` в живых `/etc/wireguard/{antizapret,vpn}.conf` **и** в шаблонах `/etc/wireguard/templates/*.conf` |

Живые конфиги WireGuard рендерятся из шаблонов (`client.sh`), поэтому панель правит оба места — иначе `wg-quick` поднял бы интерфейс со старым MTU. Клиентские шаблоны (`*-client-*.conf`) строки MTU не содержат, их не трогаем; профили клиентов пересобирать не нужно.

Применяются только изменённые значения: перезапускаются затронутые службы (OpenVPN и/или `wg-quick`), а при неудаче конфиги возвращаются как были. Кнопка «Применить MTU» активна, только когда значение отличается от текущего.

Панель правит **конфиги на диске**, но не `MTU=` в `/root/antizapret/setup`: это значение установщик спрашивает заново при каждом запуске `setup.sh`. Если после смены MTU из панели обновлять AntiZapret через `setup.sh`, укажите там то же значение — иначе установщик перезапишет `tun-mtu` и `MTU =` своим.

### DCO

Переключатель **OpenVPN DCO** повторяет `openvpn-dco.sh`: при включении в конфигах остаётся `data-ciphers "AES-128-GCM:AES-256-GCM:CHACHA20-POLY1305"`, при выключении добавляются CBC-шифры и `disable-dco`. **Включение опасно для старых клиентов:** профили с CBC-шифрами перестанут подключаться. Нужен OpenVPN 2.7 и поддержка DCO в ядре — иначе служба не поднимется и панель вернёт прежние конфиги.

### Патч антицензуры OpenVPN

Селект **1–4** запускает `/root/antizapret/patch-openvpn.sh N` (1 — снять, 2 — Random, 3 — Strong, 4 — Error-Free). Это **сборка OpenVPN из исходников**: несколько минут, узел кратко остаётся без OpenVPN, нужен доступ в интернет и место на диске. Панель ждёт завершения (до 30 минут) и показывает хвост вывода скрипта; вкладку закрывать нельзя. Применяется **только на выбранном узле** — на репликах запустите отдельно. Вывод скрипта виден в карточке до перезагрузки страницы.

### Протоколы

Переключатели **OpenVPN UDP/TCP** и **WireGuard/AmneziaWG** делают `systemctl enable --now` / `disable --now` для `openvpn-server@{antizapret,vpn}-{udp,tcp}` и `wg-quick@{antizapret,vpn}` — как `setup.sh` при установке. Панель также записывает результат в `setup` (`OPENVPN_UDP_ENABLE`, `OPENVPN_TCP_ENABLE`, `WIREGUARD_ENABLE`), чтобы мониторинг и авто-перезапуск не считали выключенный протокол упавшим, а включённый — отсутствующим; `setup.sh` при обновлении эти ключи всё равно спросит заново. **Выключение отключает клиентов этого протокола**: они не подключатся, пока протокол не включат снова (файлы профилей остаются на диске). Подтверждение требует ввести имя узла. На репликах HA протоколы не меняются автоматически — повторите на каждой.

## Несколько адресов подключения

На странице **Конфиг AntiZapret** откройте вкладку **OpenVPN (панель)** (доработки панели, не файл `setup` AntiZapret). Там можно задать **упорядоченный список** IP или доменов (до 8) на **активном узле**. Порядок сверху вниз — порядок, в котором клиент OpenVPN пробует адреса. Список свой **на каждом узле** (смотрите активный узел в шапке).

Нажмите **Сохранить адреса** — список пишется в базу панели. **Первый адрес — слот входа:** если используете российский `proxy.sh`, ставьте его первым. Непустой список при сохранении записывает этот адрес в `OPENVPN_HOST` на узле (best-effort); кнопка allow-ips берёт только его; остальные строки — запасные `remote` только для OpenVPN. Если список **очистить**, в скачанном `.ovpn` останутся remote как у AntiZapret; значение `OPENVPN_HOST` панель при очистке **не меняет**. Поле OpenVPN на вкладке **Параметры setup** при непустом списке только для просмотра (метка «из списка»).

### Как панель подставляет адреса

| Когда | OpenVPN (`.ovpn`) | WireGuard / Amnezia / AWG 2.0 |
| ------- | ------------------- | --------------------- |
| **Скачивание** (сайт, QR, Telegram, публичная ссылка) | Несколько строк `remote` в порядке списка | `Endpoint` = **WIREGUARD_HOST** из setup (порт из шаблона / az-awg2). Список OpenVPN remote сюда **не** подставляется, пока не включена галочка «Также для AmneziaWG / WireGuard / AWG 2.0» |
| **После пересборки профилей** из панели (`client.sh 7` / recreate) | Те же multi-`remote` записываются в `.ovpn` **на диске** узла (если список непустой) | Диск не трогается |
| **Только сохранение списка** (без recreate) | Диск не переписывается; новый порядок появится при скачивании и при следующей пересборке из панели | — |

Галочка **«Также для AmneziaWG / WireGuard / AWG 2.0»** — первый адрес списка пишется в `WIREGUARD_HOST` и при выдаче попадает в `Endpoint` стокового `-am.conf` / `-wg.conf` и профилей **AZ-AWG2** (порт не меняется). Для стока нужен `proxy.sh` с UDP **52443/52080** (и 51080/51443). Для AmneziaWG 2.0 порты другие (рандом az-awg2) — на RU добавьте DNAT вручную, см. [proxy-nodes.md](proxy-nodes.md#amneziawg-20-через-прокси). Без галочки AWG/AWG2 идут на `WIREGUARD_HOST` из setup.

Пересборка из панели — это действия вроде «пересобрать профили», часть CIDR/фоновых задач и смена shared domain в HA. **Push full / HA restore**, где `client.sh 7` намеренно не вызывается, диск multi-remote **не** патчат.

### Пример порядка на разных узлах

На первом зарубежном сервере: `proxy.rus.example` → `server1.example` → `server2.example`.
На втором — наоборот: `proxy.rus.example` → `server2.example` → `server1.example`.
Клиент с тем же ключом получит разный порядок `remote` в зависимости от того, с какого узла скачал профиль.

### Прокси AntiZapret и allow-ips

Российский прокси ставится **отдельно** скриптом AntiZapret — см. [Настроить прокси-сервер](https://github.com/GubernievS/AntiZapret-VPN#настроить-прокси-сервер). Панель **не** устанавливает и не запускает `proxy.sh`; в списке указывают только его адрес. Один такой прокси направляет трафик на **один** зарубежный сервер (`DESTINATION_IP`). Полная инструкция по прокси в панели: [proxy-nodes.md](proxy-nodes.md).

IP прокси должен быть в `allow-ips.txt` на VPN-сервере — иначе сервер может отклонить подключения с прокси. На вкладке **OpenVPN (панель)** есть кнопка **«Добавить первый адрес в allow-ips»**: она дописывает **только первый** адрес сохранённого списка в `allow-ips.txt` на этом узле (повторно тот же адрес не дублирует). Список должен быть сохранён; черновик без «Сохранить адреса» кнопка не использует. Можно по-прежнему править файл вручную в [Редакторе файлов](edit-files.md).

### Обновление AntiZapret и `setup.sh`

Список живёт в панели и **не пропадает** после `setup.sh`. Но `setup.sh` / обновление AntiZapret снова пересоздаёт шаблоны на диске: `.ovpn` на диске снова станут «стоковыми», пока панель не сделает следующую **пересборку профилей** (тогда multi-remote снова запишется на диск) или пока клиент не скачает профиль (при выдаче панель всегда подставляет список из БД).

### OpenVPN multihome (несколько IP на сервере)

Если у VPN-сервера несколько публичных IPv4 (основной интерфейс + aliases), OpenVPN без директивы `multihome` отвечает с основного IP — клиенты, подключающиеся к вторичным адресам, ломаются.

Вкладка **OpenVPN (панель)** содержит переключатель **«OpenVPN multihome»** (по умолчанию выкл). Включение:

1. Пишет флаг в БД панели (`nodes.openvpn_multihome`, свой на каждом узле, **не** реплицируется в HA).
2. Сразу вставляет `multihome` во все server conf (`antizapret-udp|tcp`, `vpn-udp|tcp`) и перезапускает активные `openvpn-server@*`.

Флаг в БД **не пропадает** после `setup.sh` (`bash <(wget … setup.sh)`). Именно `setup.sh` затирает `/etc/openvpn/server/*.conf` стоковыми шаблонами без `multihome`. `doall.sh` списки обновляет и **не** переписывает эти server conf.

Восстановление из панели: откройте **Конфиг AntiZapret → OpenVPN (панель)** — если флаг включён, а на диске директивы нет, панель **сама** снова пропишет `multihome` и перезапустит только **включённые** в `setup` OpenVPN-службы (`OPENVPN_UDP_ENABLE` / `OPENVPN_TCP_ENABLE`; при `OPENVPN_TCP_ENABLE=n` TCP unit’ы не трогает). Есть и кнопка **«Восстановить»**. Скрипты AntiZapret панель не меняет. WireGuard для multi-IP не требует `multihome`.

API: `GET/PUT /nodes/{id}/openvpn-multihome`.

### OpenVPN Buffer Guard (ENOBUFS)

На той же вкладке **OpenVPN (панель)** — блок **OpenVPN Buffer Guard**: защита общего UDP-сокета OpenVPN от «шторма» ошибок **ENOBUFS** (`No buffer space available`) в journalctl. Типичный контекст — shared UDP / DCO и «шумные» клиенты. Настройки **свои на каждом узле**, хранятся в БД панели; **`setup.sh` AntiZapret не меняются**.

Вверху карточки всегда показывается предупреждение: Buffer Guard **не устраняет** корневую причину (лимиты ядра, DCO, поведение клиентов), а помогает не уронить общий сокет. Рекомендуется сначала режим **«Только уведомлять»**.

| Элемент | Поведение |
| -------- | ----------- |
| **По умолчанию** | Выключено (`enabled=false`). Режим **«Только уведомлять»** (`notify`), порог **40** ошибок за **60** с. Пока не включите переключатель, фоновый worker только снимает истёкшие временные баны |
| **Включить Buffer Guard** | Автоматические действия (kill / restart / бан) выполняются только при **фоновых** проходах worker (~каждые 20 с на **online**-узлах с включённым guard) |
| **Режим** | `notify` — только фиксация и оповещения; `kill` — отключить клиента с максимумом ENOBUFS; `kill_restart` — отключить и при продолжении шторма перезапустить unit OpenVPN; `kill_restart_temp_ban` — то же + временный бан в `banned_clients` (AccessPolicy) |
| **Рекомендуемый порог** | Зависит от режима (окно по умолчанию **60** с): см. таблицу ниже. В UI показывается подсказка; кнопка **«Применить рекомендацию»** подставляет порог для **текущего** режима. **Смена режима сама порог не меняет** — только по кнопке или вручную |
| **Дополнительно** | Порог ENOBUFS за окно, длина окна (сек), пауза между срабатываниями (cooldown), задержка перед эскалацией до restart, длительность временного бана; чекбоксы юнитов `antizapret-udp/tcp`, `vpn-udp/tcp` (по умолчанию смотрятся `antizapret-udp` и `vpn-udp`) |
| **Последнее событие** | Сводка по последнему инциденту на узле (unit, CN, режим, результат) |
| **Проверить сейчас** | Ручной анализ журналов **без** kill/restart/бана (даже если guard включён). При превышении порога — предупреждение в UI; событие пишется в историю |

Рекомендуемые пороги (ошибок ENOBUFS за окно):

| Режим | Порог |
| ------- | ------: |
| Только уведомлять (`notify`) | 40 |
| Кик CN (`kill`) | 80 |
| Кик → restart (`kill_restart`) | 120 |
| Кик → restart → временный бан | 150 |

Узлы, где в БД остались **заводские** значения порога **500** и окна **60** с (из ранней версии панели), при первом обращении к настройкам **однократно** получают рекомендованный порог для **текущего** режима; остальные сохранённые пороги не трогаются.

При превышении порога панель шлёт **AdminNotify** в Telegram (тип **`openvpn_buffer_guard_triggered`**, по умолчанию включён в [Telegram → Уведомления](Telegram.md)) — узел, unit, число ENOBUFS и «шумный» CN. Пустой журнал за окно не считается ошибкой; сбой только при недоступном `journalctl`.

На удалённых узлах отключение клиента идёт через API адаптера узла; на локальном хосте панели — через management-сокет OpenVPN.

API: `GET/PUT /api/openvpn-buffer-guard/settings`, `GET /api/openvpn-buffer-guard/events`, `POST /api/openvpn-buffer-guard/scan` (параметр `node_id`).

### Трафик

Счётчики идут на **зарубежном VPN-узле**, где открыта сессия. Прокси в статистике панели отдельно не учитывается (`real_address` часто выглядит как IP прокси). Без HA Sync Group счётчики по узлам **раздельные**. С HA — на странице [Мониторинг трафика](traffic-monitoring.md) по-прежнему сумма по группе.

## Пошаговые сценарии

### Включить маршрутизацию для сервиса (например, Discord)

1. Откройте **Конфиг AntiZapret**
2. Найдите раздел **Маршрутизация трафика**
3. Включите нужный переключатель (Discord, Telegram и т.д.)
4. Нажмите **Сохранить**
5. Нажмите **Применить (doall.sh)** — без этого изменения не активируются

### Изменить резервные порты

1. Откройте раздел **Резервные порты**
2. Измените значения портов
3. **Сохранить** → **Применить (doall.sh)**
4. Сообщите клиентам новые порты, если они используют резервное подключение

#### Конфликт `OPENVPN_BACKUP_TCP` с портом 443

Флаг **OPENVPN_BACKUP_TCP** поднимает OpenVPN TCP на портах **80, 443, 504, 508**. Если панель публикует HTTPS на **443** (`HTTPS_PUBLIC_PORT`, по умолчанию), после `doall.sh` nginx и панель станут недоступны.

- Перед включением смените **Публичный порт HTTPS** в **Настройки → Адрес сайта и HTTPS** ([инструкция](nastrojki/set-i-publikaciya.md)).
- В UI при включении на 443 показывается подтверждение и постоянное предупреждение; API `PUT /routing/antizapret-settings` возвращает `warnings` (сохранение не блокируется).
- При установке (`install.sh`), если в `{ANTIZAPRET_PATH}/setup` уже стоит `OPENVPN_BACKUP_TCP=y`, а HTTPS панели будет на 443 (режимы nginx `le` / `selfsigned` / `nginx_custom`), флаг принудительно сбрасывается в `n` до настройки nginx.

## Кнопки

| Кнопка | Что делает | Когда использовать |
| -------- | ------------ | ------------------- |
| **Обновить** | Загружает текущие настройки с сервера | Если кто-то менял их вручную |
| **Сохранить** | Записывает изменения на узел | После любых правок |
| **Применить (doall.sh)** | Активирует настройки на VPN-сервере | Всегда после сохранения |

> После **Сохранить** может появиться предупреждение «Требуется применение» — это значит, что нужно нажать **Применить (doall.sh)**. UI **не** вызывает apply автоматически после сохранения.

### HA-группа (`sync_mode=auto`)

- **Сохранить** (`PUT /routing/antizapret-settings`) реплицирует те же ключи `setup` на все replica группы.
- **Применить (doall.sh)** (`POST /routing/apply`) ставит в очередь apply на **primary** и **отдельную фоновую задачу на каждую replica**. Ошибка на одной replica не отменяет apply на primary.
- Опционально для API/скриптов: `PUT /routing/antizapret-settings?apply=true` — после репликации настроек сразу enqueue apply (только admin, только при HA `sync_mode=auto` на primary). Ответ API — как у обычного PUT (результат primary).

Подробнее про sync groups: [NodeSync.md](NodeSync.md).

### `ANTIZAPRET_HA_SETTING_EXCLUDE`

При репликации setup в `sync_mode=auto` панель может отфильтровать node-local ключи (`filter_ha_replicable_settings`):

| Реплицируется | Не реплицируется |
|---------------|------------------|
| Все ключи из `ANTIZAPRET_PARAMS`, включая `ANTIZAPRET_WARP`, `VPN_WARP`, `WARP_PROTECTION`, `WARP_MTU`, `openvpn_host` → `OPENVPN_HOST`, `wireguard_host` → `WIREGUARD_HOST` (HA: `shared_domain` / `shared_domain_wireguard`) | Сейчас пусто (`ANTIZAPRET_HA_SETTING_EXCLUDE = {}`) |
| Partial update: только поля из текущего PUT | Строки вне `ANTIZAPRET_PARAMS` (напр. `OPENVPN_LOG`) — panel API их не шлёт |

Константа в коде: `ANTIZAPRET_HA_SETTING_EXCLUDE` (`antizapret_params.py`).

**`ANTIZAPRET_WARP` / `VPN_WARP` / `WARP_PROTECTION`** — встроенный Cloudflare WARP в setup AntiZapret (не AZ-WARP / Warper). Если реплика ещё на формате `y/n`, режимы `3`/`4` с primary на неё не запишутся (ошибка в журнале синхронизации) — обновите AntiZapret-VPN на реплике. Они **реплицируются** вместе с остальным конфигом, чтобы оба узла вели трафик одинаково. Node-local остаётся файл `warper-include-ips.txt` (см. [warper.md](warper.md), `CONFIG_FINGERPRINT_EXCLUDE`).

## Частые вопросы

**Сохранил, но ничего не изменилось**
Нужно нажать **Применить (doall.sh)** — сохранение только записывает файл, а применение перезагружает правила.

**Сколько ждать doall?**
Обычно несколько минут. Не закрывайте вкладку до завершения.

**Где редактировать списки сайтов?**
Для точечного добавления доменов используйте [Редактор файлов](edit-files.md). Здесь — общие переключатели сервисов.

## Будьте осторожны

- **Применить (doall.sh)** перезагружает правила маршрутизации — кратковременные перебои у подключённых клиентов возможны
- **Адреса подключения** не должны совпадать с доменом панели ([Адрес сайта и HTTPS](nastrojki/set-i-publikaciya.md#не-используйте-домен-antizapret-для-панели))
- Меняйте **безопасность сервера** только если понимаете последствия
- Всегда проверяйте **активный узел** перед сохранением — в HA работайте на **primary**
