# Конфиг AntiZapret

## Зачем эта страница

Здесь меняют **основные настройки** VPN-сервера AntiZapret: какие сервисы направлять через VPN, резервные порты, безопасность и параметры WARP.

## Кто может пользоваться

Только **администратор**.

## Как открыть

Боковое меню → **Конфиг AntiZapret**.

Настройки применяются к **активному узлу** — проверьте выбор в шапке.

---

## Разделы настроек

| Раздел | О чём |
|--------|-------|
| **Маршрутизация трафика** | Discord, Cloudflare, Telegram и другие сервисы — через VPN или напрямую |
| **Резервные порты** | Альтернативные порты OpenVPN и WireGuard для обхода блокировок |
| **WARP** | Настройки Cloudflare WARP (подробнее — [warper.md](warper.md)) |
| **Безопасность сервера** | Защита самого VPN-сервера |
| **Адреса подключения** | `OPENVPN_HOST` / `WIREGUARD_HOST` и **список remote OpenVPN** (несколько адресов в `.ovpn`) — **не** домен панели |
| **Списки и хосты** | Связь с файлами доменов и IP (подробнее — [edit-files.md](edit-files.md)) |

## Несколько адресов подключения

В разделе **Адреса подключения** на странице **Конфиг AntiZapret** можно задать **упорядоченный список** IP или доменов для **OpenVPN** (до 8). Порядок сверху вниз — порядок, в котором клиент OpenVPN пробует адреса. Список свой **на каждом узле** (смотрите активный узел в шапке). WireGuard по-прежнему один адрес.

Нажмите **Сохранить адреса** — список пишется в базу панели. При скачивании `.ovpn` (сайт, QR, Telegram, публичная ссылка) панель подставляет в профиль несколько строк `remote` в этом порядке. Файлы на диске AntiZapret не переписываются.

### Пример порядка на разных узлах

На первом зарубежном сервере: `proxy.rus.example` → `server1.example` → `server2.example`.  
На втором — наоборот: `proxy.rus.example` → `server2.example` → `server1.example`.  
Клиент с тем же ключом получит разный порядок `remote` в зависимости от того, с какого узла скачал профиль.

### Прокси AntiZapret

Российский прокси ставится **отдельно** скриптом AntiZapret — см. [Настроить прокси-сервер](https://github.com/GubernievS/AntiZapret-VPN#настроить-прокси-сервер). Панель **не** устанавливает и не запускает `proxy.sh`; в списке указывают только его адрес. Один такой прокси направляет трафик на **один** зарубежный сервер (`DESTINATION_IP`).

IP прокси добавьте в `allow-ips.txt` на VPN-сервере (через [Редактор файлов](edit-files.md) или вручную) — иначе сервер может отклонить подключения с прокси.

### Обновление AntiZapret и шаблоны

Список живёт в панели и **не пропадает** после `setup.sh`. Не рассчитывайте на правку шаблонов `.ovpn` на диске — при обновлении AZ они пересоздаются; нужный порядок снова даёт панель при выдаче.

Если список **очистить**, в скачанном `.ovpn` останутся remote как у AntiZapret; значение `OPENVPN_HOST` в setup панель при очистке **не меняет**. Если список непустой, первый адрес при сохранении записывается в `OPENVPN_HOST` на узле (best-effort).

### Трафик

Счётчики идут на **зарубежном VPN-узле**, где открыта сессия. Прокси в статистике панели отдельно не учитывается (`real_address` часто выглядит как IP прокси). Без HA Sync Group счётчики по узлам **раздельные**. С HA — на странице [Мониторинг трафика](traffic-monitoring.md) по-прежнему сумма по группе.

## Пошаговые сценарии

### Включить маршрутизацию для сервиса (например, Discord)

1. Откройте **Конфиг AntiZapret**
2. Найдите раздел **Маршрутизация трафика**
3. Включите нужный переключатель (Discord, Telegram и т.д.)
4. Нажмите **Сохранить**
5. Нажмите **Применить (doall.sh)** — без этого изменения не активируются

### Изменить резервные порты

1. Откройте раздел **Резервные порты**
2. Измените значения портов
3. **Сохранить** → **Применить (doall.sh)**
4. Сообщите клиентам новые порты, если они используют резервное подключение

#### Конфликт `OPENVPN_BACKUP_TCP` с портом 443

Флаг **OPENVPN_BACKUP_TCP** поднимает OpenVPN TCP на портах **80, 443, 504, 508**. Если панель публикует HTTPS на **443** (`HTTPS_PUBLIC_PORT`, по умолчанию), после `doall.sh` nginx и панель станут недоступны.

- Перед включением смените **Публичный порт HTTPS** в [Настройки → Адрес сайта и HTTPS](/settings/vpn_network).
- В UI при включении на 443 показывается подтверждение и постоянное предупреждение; API `PUT /routing/antizapret-settings` возвращает `warnings` (сохранение не блокируется).
- При установке (`install.sh`), если в `{ANTIZAPRET_PATH}/setup` уже стоит `OPENVPN_BACKUP_TCP=y`, а HTTPS панели будет на 443 (режимы nginx `le` / `selfsigned` / `nginx_custom`), флаг принудительно сбрасывается в `n` до настройки nginx.

## Кнопки

| Кнопка | Что делает | Когда использовать |
|--------|------------|-------------------|
| **Обновить** | Загружает текущие настройки с сервера | Если кто-то менял их вручную |
| **Сохранить** | Записывает изменения на узел | После любых правок |
| **Применить (doall.sh)** | Активирует настройки на VPN-сервере | Всегда после сохранения |

> После **Сохранить** может появиться предупреждение «Требуется применение» — это значит, что нужно нажать **Применить (doall.sh)**. UI **не** вызывает apply автоматически после сохранения.

### HA-группа (`sync_mode=auto`)

- **Сохранить** (`PUT /routing/antizapret-settings`) реплицирует те же ключи `setup` на все replica группы.
- **Применить (doall.sh)** (`POST /routing/apply`) ставит в очередь apply на **primary** и **отдельную фоновую задачу на каждую replica**. Ошибка на одной replica не отменяет apply на primary.
- Опционально для API/скриптов: `PUT /routing/antizapret-settings?apply=true` — после репликации настроек сразу enqueue apply (только admin, только при HA `sync_mode=auto` на primary). Ответ API — как у обычного PUT (результат primary).

Подробнее про sync groups: [NodeSync.md](NodeSync.md).

### `ANTIZAPRET_HA_SETTING_EXCLUDE`

При репликации setup в `sync_mode=auto` панель может отфильтровать node-local ключи (`filter_ha_replicable_settings`):

| Реплицируется | Не реплицируется |
|---------------|------------------|
| Все ключи из `ANTIZAPRET_PARAMS`, включая `ANTIZAPRET_WARP`, `VPN_WARP`, `openvpn_host` → `OPENVPN_HOST`, `wireguard_host` → `WIREGUARD_HOST` (общий `shared_domain` в HA) | Сейчас пусто (`ANTIZAPRET_HA_SETTING_EXCLUDE = {}`) |
| Partial update: только поля из текущего PUT | Строки вне `ANTIZAPRET_PARAMS` (напр. `OPENVPN_LOG`) — panel API их не шлёт |

Константа в коде: `ANTIZAPRET_HA_SETTING_EXCLUDE` (`antizapret_params.py`).

**`ANTIZAPRET_WARP` / `VPN_WARP`** — встроенные флаги Cloudflare WARP в setup AntiZapret (не AZ-WARP / Warper). Они **реплицируются** вместе с остальным конфигом, чтобы оба узла вели трафик одинаково. Node-local остаётся файл `warper-include-ips.txt` (см. [warper.md](warper.md), `CONFIG_FINGERPRINT_EXCLUDE`).

## Частые вопросы

**Сохранил, но ничего не изменилось**  
Нужно нажать **Применить (doall.sh)** — сохранение только записывает файл, а применение перезагружает правила.

**Сколько ждать doall?**  
Обычно несколько минут. Не закрывайте вкладку до завершения.

**Где редактировать списки сайтов?**  
Для точечного добавления доменов используйте [Редактор файлов](edit-files.md). Здесь — общие переключатели сервисов.

---

## Будьте осторожны

- **Применить (doall.sh)** перезагружает правила маршрутизации — кратковременные перебои у подключённых клиентов возможны
- **Адреса подключения** не должны совпадать с доменом панели ([Адрес сайта и HTTPS](nastrojki/set-i-publikaciya.md#не-используйте-домен-antizapret-для-панели))
- Меняйте **безопасность сервера** только если понимаете последствия
- Всегда проверяйте **активный узел** перед сохранением — в HA работайте на **primary**
